# Quantum architecture & training

## Circuit

The classifier is an ``n_qubits``-qubit VQC (four by default, eight in the selected Sangria model, run `q8_b6_pi`) with data re-uploading: the encoding block is interleaved before every trainable layer rather than applied once at state preparation.

- **Encoding block:** Hadamard followed by ``R_z(x_i)`` on qubit ``i``, where ``x_i \in [0, \phi]`` is the ``i``-th normalised feature and ``\phi`` = `[training] phase_span` ``\times \pi``, by default ``\pi``. ``R_z`` is ``2\pi``-periodic with ``R_z(2\pi) = -I``, so the full period sends both ends of the interval to the same state and a feature saturated above the training range is encoded as one at the floor; ``\pi`` is the widest span whose ends are distinct. The span is persisted with the scaler, and artifacts written before it existed load with the ``2\pi`` they were trained on. The number of qubits equals the feature dimension.
- **Trainable layer:** hardware-efficient ansatz — ``R_y`` and ``R_z`` rotations on every qubit followed by a ring of CNOT gates. Each layer holds ``2 n_\mathrm{qubits}`` parameters; the default configuration uses four layers.
- **Measurement:** the Pauli-``Z`` expectation is averaged over all qubits and mapped to a class probability ``p = (1 - \langle Z \rangle)/2``. Pulled back through the CNOT ring, every measured ``Z_k`` is a product of ``Z`` operators, which commutes with the ``R_z`` rotations of the last layer: those ``n_\mathrm{qubits}`` parameters do not affect the output and receive a zero gradient (the architecture of the reference paper is kept as is; the test suite verifies the property).

Parameters are initialised from a zero-mean normal distribution with standard deviation 0.5.

## Evaluation protocol

Sliding windows overlap by 90 %, so neighbouring windows are nearly identical and any random split would place copies of the same signal on both sides. The training stage therefore partitions the chronologically ordered windows into three contiguous blocks — training, validation, and test, holding `train_fraction`, `validation_fraction`, and the remainder of the windows (defaults 0.7, 0.15, 0.15) — separated by a buffer of one window length (`window_size / step_size` windows) so that no window straddles two blocks (`chronological_split`). The block ranges are written to `split.toml` in the run directory; the feature scaler is fitted on the training block alone.

- The validation block drives early stopping. The decision threshold is fitted on the calibration block selected by `threshold_block` (`threshold_rows`): the validation block alone by default, or, with `held_out`, validation and test pooled across the buffer between them, which doubles the mission time behind the fitted false-alarm rate. The test block is scored once, after training, with the fitted threshold; under `held_out` it is part of the calibration set and its metrics are no longer an independent check of the operating point, which a separate observation record must provide.
- Window labels are positive whenever a labelled sample falls inside the window (a few per cent to a few tens of per cent of the windows, depending on the label span). The binary cross-entropy weights the positive term by the negative-to-positive count ratio of the training block (`class_weight = "balanced"`) unless disabled.
- Metrics are reported at window level (precision, recall, ``F_1``, balanced accuracy, ROC AUC) and at event level (`event_metrics`): an event is a contiguous run of positive labels and counts as detected when any window inside it is alarmed; a false-alarm episode is a contiguous run of alarmed windows outside the labelled spans; the operational false-alarm rate is the number of such episodes per 30 mission days of the evaluated block.

## Training

- Class-weighted binary cross-entropy over mini-batches of the training block, the rows drawn in one random permutation per epoch.
- The circuit is built once per task (`CircuitWorkspace`): the encoding angles of a sample are set in it and the gates are applied in place to a preallocated register (`predict_probability!`). `predict_probability` remains the non-mutating definition of the forward pass, which rebuilds the gates of every sample; the in-place scores equal its scores bit for bit.
- The gradient is taken by adjoint differentiation in Yao's reversible mode (`accumulate_gradient!`; [JonesGacon2020](@cite), [LuoEtAl2020](@cite)): after the forward pass a second register is seeded with ``\bar Z |\psi\rangle``, the circuit is undone gate by gate on both registers, and every rotation contributes its derivative where it is undone. That is three passes over the circuit and two registers, whatever the number of parameters. For the eight-qubit circuit of four layers it costs 0.15 ms per sample on one thread, 3.5 forward passes, where a Zygote tape over the non-mutating forward pass costs 8 ms and allocates eighty times the memory.
- The Zygote tape stays as the reference gradient (`gradient_method = "zygote"` under `[training]`). The two agree to single-precision rounding, about ``10^{-6}`` relative, and so does a central difference of a double-precision copy of the circuit; the suite checks all three against each other. Retrained with the adjoint gradient, the two configurations of this manual at their four seeds reproduce the reference runs: the same selected epoch, loss histories within ``5 \times 10^{-7}``, thresholds within ``1.2 \times 10^{-7}``, and the same counts of detected coalescences and false-alarm episodes on the blind year.
- Batch gradients and forward passes run over the Julia threads (`batch_gradient`, `predict_all`; `threaded` under `[training]`, on by default). The batch is cut into chunks of four samples; the tasks draw chunks from a shared counter, and the chunk sums are stored by chunk index and added in that order, so the result depends neither on the thread count nor on the scheduling, and serial and threaded evaluation give the same bits. (Under the Zygote reference the serial path is one tape over the batch and differs from the threaded one by the rounding of the accumulation order.) Start Julia with `-t auto` (or `JULIA_NUM_THREADS`) to use the available CPU threads; on a processor with six performance cores the gain saturates near six threads.
- Adam (`Optimisers.jl`) with exponential learning-rate decay and patience-based early stopping on the validation loss; the best model is persisted per run as a JLD2 artifact holding the parameter vector, hyperparameters, the feature scaler, and run metadata (the circuit is rebuilt on load).
- Quantum registers use `ComplexF32` to match the `Float32` parameter vector.

## Decision threshold

After training, `threshold_sweep` evaluates the window- and event-level statistics of the calibration block at every candidate threshold (the quantiles of its scores) — the event-level operating characteristic of the block, persisted as `threshold_sweep.csv` and drawn as the `threshold_sweep` figure (event and window recall, and false-alarm episodes per 30 days, against the threshold). `select_threshold` then fits the threshold on it by the `threshold_criterion` of `[training]`:

- `far` (default): the operating point of an alert trigger. A candidate is admissible when its false-alarm episode rate does not exceed `target_far_per_30d` and its window false-positive rate — the alarm duty cycle on unlabelled windows — does not exceed `target_fpr`. Candidates are scanned from the highest downwards and the threshold is the lowest candidate of the admissible range that starts at the top, i.e. the highest recall reachable while alarms remain short and isolated. The scan direction matters because the episode count is not monotone in the threshold: as the threshold falls, spurious episodes first multiply and then merge into a permanently raised alarm charged with only a few long episodes, which an ascending scan would accept as soon as the target admits a few episodes per month. The default target of three episodes per 30 days is the trigger-level policy: a trigger requires a characterisation pass of the low-latency chain, not an alert, and the observed rate on a block of ``T`` days is a Poisson count of mean ``3T/30``, so the block must span of the order of two months for the fit to be meaningful; on the eight-day sanity records the criterion reduces to the duty-cycle constraint.
- `fpr`: the lowest threshold whose window-level false-positive rate does not exceed `target_fpr`.
- `youden`: the maximiser of ``\mathrm{TPR} - \mathrm{FPR}``; it needs both classes in the fitting block and falls back to `fpr` with a warning otherwise.

The block the criterion is fitted on is chosen by `threshold_block`:

- `validation` (default): the validation block alone, the classical split.
- `held_out`: validation and test pooled, including the buffer windows between them so that the range stays contiguous in mission time and an alarm episode spanning the join is counted once.

`held_out` is motivated by the Poisson argument above. The fitted rate rests on the false-alarm episodes counted on the block, and its relative error is the inverse square root of that count; a block of the order of two months typically contains fewer than five, so an operating point placed on it carries a 50 % uncertainty and need not hold on another observation record. Pooling doubles the exposure without information leakage into the model (the test block is scored once after training and enters neither model selection nor early stopping), but the test block is then no longer independent: its operating-point metrics become in-sample. It is therefore optional, intended for records that come with a separate blind product, as Sangria does, and the default is the validation block. `threshold.toml` records the episode count behind the fitted rate (`fit_false_alarm_episodes`) and the training stage warns below `[training] min_fit_episodes` (five by default).

The threshold, the criterion actually applied, the targets, the block and the rates on it at the threshold (`fit_*`), and the validation AUC are persisted as `threshold.toml` next to the model; `metrics.toml` holds the validation- and test-block metrics of the run.

## Inference

The inference stage loads the model, the scaler, and the persisted threshold, scores a feature table, and writes per-window probabilities and decisions. The window geometry comes from the sidecar `<features>.toml` written by the pre-processor. With labels it reports the window- and event-level metrics of the evaluated rows to `metrics.toml` and their operating characteristic to `threshold_sweep.csv` — a post-hoc diagnostic of where the persisted threshold sits on the evaluated data; the threshold itself is never refitted at inference. `--block validation` or `--block test` restricts the evaluation to one block of the training table through the run's `split.toml`. Blind inference (`--labels ""`) needs no labels. Figures: the mission trace with the threshold, the ROC curve, the operating characteristic with the applied threshold, detection sensitivity versus matched-filter SNR, and the score distributions.

## Pipeline architecture

The pipeline is a library with thin command-line entry points. Every stage is a typed, documented function of the package taking the parsed TOML configuration and returning a named tuple of its artifacts and results, so that it can be called from a script, a test, or another package alike:

| Stage | Function | Script |
|---|---|---|
| Telemetry simulation | `generate_telemetry(config; run_id, output)` | `scripts/generate_data.jl` |
| Truth-stream labels (LDC) | `label_truth_stream(config; h5_file, truth_csv, output_prefix)` | `scripts/label_ldc.jl` |
| Window features | `preprocess_record(config; h5_file, tdi_group, label_file, output_prefix, force)` | `scripts/preprocess_ldc.jl` |
| Training | `train_classifier(config; run_id, test_mode, on_epoch)` | `scripts/train.jl` |
| Inference | `evaluate_classifier(config; run_id, model, features, labels, block)` | `scripts/infer.jl` |
| Payload export (telemetry) | `export_telemetry_payload(config; h5_file, tdi_group, catalog, output_prefix)` | `scripts/export_telemetry_payload.jl` |
| Telemetry replay | `replay_run` / `follow_run` on `open_telemetry_run(run_dir)` with `detector_from_run(model)` | `scripts/infer_telemetry.jl` |

- **Layers.** The pipeline is built from three packages, each depending only on the ones before it. [StreamingInference.jl](https://github.com/PaulGoG/StreamingInference.jl) holds everything that does not depend on the physical domain or the method: configuration, provenance, signal processing, features, evaluation, the estimator interface (`AbstractWindowScorer`, `window_score`, the `Stateless`/`Stateful` memory trait) and the streamed replay. [MilliHertzBase.jl](https://github.com/PaulGoG/MilliHertzBase.jl) holds the gravitational-wave layer: noise model, response, waveforms, LDC products, the whitening PSD of a TDI record, and the generation, pre-processing, labelling and payload-export stages. This package is the third: the classifier (`VQCScorer`, training, persistence), one scorer of the streaming detector. `using MilliHertzQML` exports the public names of all three, and the two modules are reachable as `MilliHertzQML.StreamingInference` and `MilliHertzQML.MilliHertzBase`.
- **Channel modes.** `[tdi] channels` names the noise-orthogonal TDI combinations a product is made from: `"A"` (the default, and the mode of every product made before the modes existed) or `"AE"`. In the mode `"AE"` MilliHertzBase.jl whitens A and E each by its own PSD and combines the features of the two channels into as many as the mode A has, so the circuit is unchanged. `[preprocessing] channel_combination = "max"` (default) keeps of every feature the value farthest towards a signal — the larger band power and spread, the smaller entropy; `"mean"` takes the features of the averaged periodogram, the excess power of the network. The average halves the excess power of a source that one channel sees while the noise spread falls only by ``\\sqrt 2``, so it is the better statistic only for a source split equally between the channels: on the Sangria blind year it delays the alert of one such coalescence by 12 to 21 hours, which the maximum does not. The labelling stage adds the signal onset of the two-channel network (`signal_start_index_ae`), from the root of the summed squared window SNRs. Every product records its mode; training refuses a configuration whose mode differs from that of its feature table, and inference refuses features of another mode than the model was trained on. In a streamed replay the detector of such a model carries one whitening PSD per channel, conditions every channel on its own (one causal PSD estimate each), and combines their features as its training product did. The telemetry producer carries one payload column, the A channel: `scripts/infer_telemetry.jl --tdi-file` takes the delivery of the mission and serves the channels of every delivered batch from the TDI record the payload was exported from, after checking that the A channel of the record is the payload the mission carried (`ScheduledRecordRun`). A mission over a later stretch of the record names the row its payload starts at (`--tdi-first-row`). The delivery of a batch is thereby common to its channels, as it is on LISA, where the combinations are formed on the ground from the same telemetry and the volume on the link does not depend on how many of them an analysis reads. The snapshot of the replay records `link_volume_channels`: 1, or the number given as `--link-volume-channels` for a mission whose production rate was scaled. Alerts are credited from the onset of the channels the detector reads. The mode `"AET"` is in the vocabulary and is refused by the pre-processing stage: no features of the T channel are defined. A veto on the band powers of T was examined on the LDC-2b (Spritz) records in an exploratory analysis and not adopted: below 1 mHz T responds to the signal on arms of unequal length, and at higher frequencies it did not separate the glitches that raise alarms from noise.
- **Classical controls.** `[model] kind` selects the classifier: `"circuit"` (the default, the variational quantum classifier), `"logistic"` (a logistic regression) or `"perceptron"` (one hidden layer of `hidden_units` tanh units). The controls (`ClassicalControl`) take the encoded features of the circuit divided by the encoding span, are initialised from the same distribution, and go through the same training stage — blocks, scaler, weighted cross-entropy, optimiser, early stopping, threshold rule — the same inference stage and the same streamed replay (`ClassifierScorer`); the model artifact records which classifier it holds. Their gradient is analytic. The configurations `configs/experiments/q8_b6_s001_logistic.toml` and `q8_b6_s001_perceptron.toml` (and the `_ae_` pair) are the controls of the streaming configuration.
- **Configuration.** The TOML file is the single source of truth (the `config.jl` of each layer and `src/settings.jl`): each section is read through a settings function (`generation_settings`, `preprocessing_settings`, `model_settings`, `training_settings`, `inference_settings`, `ldc_settings`, `resource_settings`, `telemetry_settings`) that validates types, bounds, and enumerated choices on load and fails with the offending key. The scripts add only a run identifier, a test-mode switch, and the location of external inputs (`julia scripts/<stage>.jl [configs/default.toml] [--run-id ID] ...`); relative paths resolve against the package root whichever environment is active.
- **Provenance.** Every snapshot written by a stage (`write_toml`) carries the hardware fingerprint, the git description of the package tree with its dirty flag and the package version, the packages of the pipeline with the revision each is tracked by (`layer_provenance`: the two layers at their pinned commits and this package), and the wall-clock time; model artifacts carry the same in their metadata. Snapshots are written to be publishable: the host appears as an anonymous `machine_id` (a truncated SHA-256 digest of its name, which distinguishes machines without naming one), the `versioninfo` output has the home directory replaced by `~`, and input paths are recorded by `provenance_path` — relative to the package root when they lie inside it, by file name alone when they do not, so that no account name or directory layout of the running machine reaches an artifact. Existing files are never overwritten: `write_toml` and `write_csv` move a previous file to `<stem>_#k<ext>` first, the `safesave` convention of DrWatson. Feature products record the SHA-256 digest of every parameter that determines them (`parameter_digest`), their inputs identified by the SHA-256 of their content (`content_digest`) rather than by path or modification time, and preprocessing reuses an identical product unless forced. Feature and label sidecars carry a `[product]` table (`product_table`): the kind of product, the channels it was made from, the schema of its tables, and the content digests of its parents.
- **Resource guard.** `[resources]` holds `max_memory_gib` and `warn_memory_gib`. Before allocating, a stage estimates its memory — for training, two ``2^{n}`` complex single-precision statevectors per task under the adjoint gradient, or under the Zygote reference the statevector copied per gate application for every sample of the batch and every layer, forward and reverse (`training_memory_estimate_gib`); for record processing, a few record-length arrays (`record_memory_estimate_gib`) — and refuses to start above the maximum or warns above the warning level (`check_memory`).
- **Timing.** Stages accumulate wall time and allocations in a package-wide `TimerOutput`; the scripts print its table at the end (`report_timing`).
- **Command line.** `--test-mode` restricts training to the first `test_mode_samples` windows and `test_mode_epochs` epochs of `[training]` for a quick check; `--seed` overrides `[training] seed` for one run and is recorded in its configuration snapshot, so the seed of a run can be read from its own artefacts. Training and inference use every Julia thread of the session (`julia -t auto`, or `JULIA_NUM_THREADS`); `threaded = false` under `[training]` selects the serial path.
- **Detector response.** The simulator's response is an interface of the package (`src/response.jl` of MilliHertzBase.jl): `SkyAveragedResponse` records one strain referred to the sensitivity, and the constellation response — antenna patterns of the A and E channels on the LISA orbits, Doppler phase, transfer roll-off — is implemented by the CurvatureDistinguishability extension against that interface (`lisa_response`, `source_frame`, `project_spectrum`, `project_series`), so that the core carries neither the upstream's optimisation stack nor its plotting dependencies. The generation stage dispatches on the response (`simulate_record`); `[generation] response = "lisa"` without the extension loaded fails with the name of the package to load.
- **Figures.** The figure functions are declared in the package (the `visualization.jl` of each layer) and implemented by a CairoMakie extension of the same layer, so no layer carries a plotting dependency; the figures of the gravitational-wave layer and of the classifier draw on the theme, legend and tick helpers of the domain-general layer. One theme serves every figure: the base layout of a 900 × 600 pt single panel (350 pt per further stacked panel, 180 pt per auxiliary strip, `figure_size`), 26 pt type, 3 pt data lines, Computer Modern through MathTeXEngine, boxed axes with inward ticks and a faint dashed grid, no titles, a horizontal legend above the axes, series families in Okabe–Ito colours with roles in line style (data solid, thresholds dashed, chance dotted) and one colour per quantity across figures (`FIGURE_COLORS`), and an axis offset multiplier for strain amplitudes that is folded into the ticks when it would be 10⁰ or 10¹. `save_figure` writes the vector PDF, a 4× PNG, and a provenance sidecar per figure recording the canvas exported, backing up earlier exports.

## Known methodological deficiencies

Retained here so the documentation reflects the code as it stands; these are the open items.

1. **Single evaluation record.** The blocks are cut from one record, so the test block carries the events of one realisation; the Sangria blind set is the independent evaluation.
2. **Model selection.** The selection statistic, the false-alarm episodes of a 55-day validation block, counts 1 to 10 episodes per run: too few to rank configurations whose rates do not differ beyond the scatter between seeds. On the Sangria grid trained at four seeds the rule selects three different configurations, one of them the worst on the blind year.
3. **Registers of ten qubits and more.** An epoch of the eight-qubit model takes about three seconds on 16 threads. From ten qubits on, the array register of Yao threads every gate application whenever Julia runs more than one thread, at a fixed register size, and up to about thirteen qubits that costs more than it gains and competes with the threads over the samples: in a 16-thread session a batch gradient of 64 samples takes 176 ms for the ten-qubit circuit of four layers against 41 ms in a single-thread session, and 237 against 185 ms at twelve qubits; at fourteen qubits the threads pay off, 382 against 851 ms. Registers of ten to thirteen qubits are therefore trained fastest with `julia -t 1` until that size can be set. Beyond it the cost is the state-vector simulation itself, which doubles with every qubit.
